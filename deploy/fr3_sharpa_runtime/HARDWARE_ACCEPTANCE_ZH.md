# 七阶段跨Prompt在线交接：实机实验验收规程

日期：2026-11-11。适用仓库`sharpa-pi05`的`tomato-subtasks-manual-deploy`。本文是实验准备与证据记录要求，不是自动运动程序，也不是硬件安全认证。日志分析工具不授予设备操作权限。

## 验证状态必须分开记录

| 项目 | 当前证据 | 不能推出的结论 |
| --- | --- | --- |
| 七阶段人工状态机、版本隔离、IPC、软件交接调度 | 已完成离线自动化验证及模拟 | 不能推出真实机器人动态安全或采摘成功 |
| 普通Soft-Prefix RTC阶段内部执行 | 团队此前已有真机使用经验，成熟实现保留 | 不能把已有经验当成本次跨Prompt交接的实机验收 |
| 同一会话的跨Prompt桥接 | 已完成软件实现、时间预算和离线测试 | 尚无本工具可认证的本次实机动态验收证据 |
| 硬件停止、接触保护、watchdog与故障响应 | 必须由具备资质人员核对现场设备、接口及实际行为 | 软件STOPPING/FAULT/COMPLETED、手部失能日志不等于双臂静止保持已确认 |
| 日志自动分析 | 可验证字段关联、时钟规则和统计计算 | 不会自动证明设备安全、抓握力或物体稳定性 |

软件回归结果与命令见[分析使用文档](EXPERIMENT_ANALYSIS.md)及[原在线切换审计](ONLINE_SWITCH_AUDIT.md)。本次开发没有自动启动真实机器人，也没有改动现有限位、桥接时间或控制算法。

## 动态验收开始前的停止条件

以下任一项未确认，不得开始动态验收；只允许继续离线检查、只读记录和无运动准备。确认责任在具备资质的实验人员，不由分析脚本代签。

- 已有明确现场授权、负责人、操作员和监护人员；实验区域隔离、人员撤离运动范围、危险与负载评估完成。
- 硬件急停可达且经现场确认有效；单一控制所有者、ROS发布者身份及SDK设备身份核对完成，没有遥操/其他执行端争用。
- 实际关节限位、速度限制、手部slew、接触/碰撞保护和watchdog有效；不得通过禁用或扩大阈值获得更高切换成功率。
- 新鲜的真实关节反馈和三路相机身份/时间关系可验证，反馈异常时的现有停止路径明确。
- 对失能后手部机械行为、果串/负载掉落风险、机械臂停止/保持方式及故障响应已有合格人员确认的处置办法。
- 当前缺少可验证的FR3双臂安全静止/保持ACK。凡本次实验安全论证依赖这项能力、暂停后自动恢复或完整停止后继续运行，都必须先补齐并单独验收；不得伪造`arms_safe=true`，不得把“命令已发出”当成“设备已安全静止”。
- 完整日志和记录链已建立，磁盘/录制能力可用，时钟身份与来源能留证；无法解释的反馈、时钟或记录缺口必须先解决。

遇到超时、反馈异常、非法目标、控制所有者变化、未知接触/抓握变化或记录链失效，执行既有故障处理。现场人员按既定安全流程处置，不以分析报告中“applied”替代实际检查，不在清理未确认时重新授权运动。

## 每次实验必须保留的证据包

1. 实验编号、日期、现场授权、操作/监护人员、场地与负载工况、机器人/双手/相机身份、开始前检查和停止条件确认记录。
2. Git完整SHA、分支、执行参数、模型及归一化资产身份/摘要、部署`run.json`、硬件/推理/执行日志；权重本身按既有资产管理，不放进分析报告仓库。
3. 原始`logs/task-events.jsonl`、**所有**`logs/control-*.jsonl`、`task-run.json`、`task-final.json`；异常/截断文件也原样保留，不重排时间、不删失败请求。包括shutdown/清理读回报告及运行中参数变化记录。
4. `analysis-manifest.json`：合成/实机/未知来源声明，每个生产者主机身份、OS boot_id、采集时的clock域，浏览器到执行端wall偏移及测量不确定度。多机器只同步Unix时间不能合并monotonic。
5. 原始bag、三路图像与反馈源时间戳、已执行目标、录制完整性与视频导出结果。当前control帧使用日志post-send时间，需独立保存硬件测量采样时间、反馈年龄、控制周期/抖动，才能进一步分析真正的动态跟踪。
6. 独立的物理结果标注：每阶段人工验收、采摘是否成功、果实/果串是否掉落或受损、抓握/接触状态、力/力矩传感器数据及标定（如具备）。这些数据与视频/日志建立可验证的时钟联系；没有证据的项目写“未测/缺失”。
7. 原日志校验摘要、分析工具提交、分析命令、清单、全部输出文件和人工复核意见。区分原始记录与派生报告，修订清单或标注时保留版本，不覆盖原始实验事实。

## 分阶段验收与记录矩阵

每项是否可开展及允许的具体运动，应由现场负责人基于设备和风险决定；本工具不会执行以下实验。

| 层次 | 应确认的事项 | 必留指标/证据 |
| --- | --- | --- |
| 无运动检查 | 版本、模型/设备身份、日志字段、时钟与输入完整性 | SHA、参数、clock域、不确定度、字段缺失/拒绝清单 |
| 原普通RTC复核 | 已有成熟路径在本次设备/负载下的行为 | 真实闭环延迟、30Hz抖动、跟踪误差、watchdog与停止行为 |
| 受限工况跨Prompt | 无负载、可控风险下的请求/桥接/实际接入 | 各时间点、旧Future、旧phase、snapshot与图像源年龄、控制帧连续性 |
| 请求扰动 | 不同phase、连续请求、重规划交替、允许条件下的延迟变化 | 成功/拒绝/替代/超时分布，失败时是否按原流程停止 |
| 反馈/接触与故障 | 由合格人员批准的专门验证，不直接拔线或制造危险 | 实际停止/保持、接触保护、故障响应、失能行为及安全状态确认 |
| 携带负载和作业 | 前序验收通过后，由现场人员逐级决定工况 | 右手稳定性、实际速度/加速度/jerk、接触力、物体状态、采摘结果 |
| 七阶段完整流程 | 同一会话、七阶段顺序与独立物理任务验收 | 软件接入与物理成功两套结果、录制完整性及所有失败样本 |

不要只保留成功视频。Chunk末端因预算不足拒绝属于必须保留的结果，不能通过延长旧轨迹、改桥接周期或放宽保护来删除失败样本。日志分析的速度/加速度/jerk不自动构成合格阈值；真实阈值、测量方式和判定责任须由有资质人员另行确认。

## 报告人工复核

- 确认报告的source_kind和实验原始来源一致。synthetic示例、GPU假观测和真实机器人记录分开，不合并成实机成功率。
- 核对request_id/run_id/version/token与具体实验；同Prompt不同阶段仍分别评估。检查去重、superseded、incomplete和所有质量警告。
- Click-to-Applied缺失时，不用登记→Applied冒名替换；worker单边回执与父进程确认分别记录。对P95/P99同时列样本数、缺失数和来源。
- 复核跟踪误差的时间对齐假设、缺口、反馈采样频率及导数噪声。没有硬件采样时间时，只能把结果称为日志帧代理指标。
- 明确软件“接入”、阶段人工“验收”、抓握稳定、接触保护与完整任务成功是不同事实。任何一项缺少独立证据均保留缺失，不由COMPLETED推断。
- 验收结论写明通过项、失败项、未测项、适用设备/负载/参数范围、停止处置及签字责任；未确认项不自动开放后续动态工况。
